### Technical Deep Dive Questions

#### Q1: "What is YOLOv8?"

**Answer:**

> "YOLOv8 stands for 'You Only Look Once' version 8 - a state-of-the-art object detection model. Unlike traditional methods that scan images multiple times, YOLO looks at the entire image once and predicts all objects simultaneously. It uses a 53-layer convolutional neural network with 3.2 million parameters for the nano version. We fine-tuned it on 50 pharmaceutical packaging images to detect holograms, tamper-proof seals, and labels with 89% mAP accuracy."

#### Q2: "How does blockchain work in your system?"

**Answer:**

> "We implemented an Immutable Cryptographic Ledger using Isolated Unit-Level Hash Chains. Instead of one massive global blockchain which causes massive database lock contention (an O(N) bottleneck), we maintain a separate hash chain for every individual drug unit. The genesis block (first scan) roots itself mathematically using a 64-zero constant. Each subsequent supply chain event is appended by hashing the previous block's hash along with the deterministic JSON serialization of the new event. This gives us infinite horizontal scalability and lightning-fast O(K) tamper verification at the edge."

#### Q3: "Explain Random Forest classifier."

**Answer:**

> "Random Forest is an ensemble learning method using 100 decision trees. Initially, our model suffered from overfitting due to tight coupling with visual features. We resolved this by implementing FeatureExtractorV2, which isolates the pipeline to 10 purely behavioral telemetry points (e.g., scan frequency, travel speed anomalies, geofence compliance). This modular architecture ensures the model classifies drugs reliably based entirely on supply chain telemetry, preventing visual discrepancies from corrupting the final verification verdict."

#### Q4: "What is Haversine formula?"

**Answer:**

> "Haversine calculates the great-circle distance between two GPS coordinates on Earth's surface. Formula: a = sin²(Δφ/2) + cos(φ1)·cos(φ2)·sin²(Δλ/2), then distance = 2R·atan2(√a, √(1-a)). This gives shortest path considering Earth's curvature. We use it to calculate drug travel speed. If Mumbai to Delhi (1153 km) happens in 10 minutes, speed = 6919 km/h > 900 km/h airplane max, indicating QR cloning."

#### Q5: "Why SHA-256 hashing?"

**Answer:**

> "SHA-256 creates a 256-bit (64 character) unique fingerprint of data. Same input always gives same hash, but tiny change completely changes output. It's one-way - can't reverse hash to get original data. Collision-resistant - virtually impossible to find two inputs with same hash. We hash drug details to create tamper-evident ID. If someone changes expiry date, hash verification fails immediately."

#### Q6: "How does the system handle concurrent ML inference without blocking the API?"

**Answer:**

> "We decoupled the heavy ML tensor operations from the FastAPI event loop using an asynchronous architecture. When an image is uploaded, FastAPI saves it locally with a UUID4 prefix to prevent race conditions and pushes the absolute file path to a Redis message broker. A background Celery worker picks up the task, loads the PyTorch models globally into RAM to prevent 'zombie worker' boot failures, executes the inference, and securely deletes the temporary file in a finally block to prevent disk space leaks. The client uses a polling mechanism synced via the UUID to retrieve the final result, ensuring the main web server remains highly responsive."

#### Q7: "How is the API secured against unauthorized access?"

**Answer:**

> "We implemented a stateless JWT authentication system paired with a Live Database Check. Passwords are securely hashed using bcrypt. To eliminate the 'Stale Claims Vulnerability'—where a revoked user maintains access until their token expires—we deliberately exclude the user's role from the JWT payload. Instead, our FastAPI dependency decodes the user ID and performs a microsecond live database lookup to verify their active status and current role. This allows instant revocation. Additionally, we protected public endpoints like /verify-image using a Redis-backed sliding window rate limiter."

### Common Questions & Answers

**Q: "Is this production-ready?"**

> "It's a working prototype demonstrating core concepts. For production: migrate to PostgreSQL, add Hyperledger Fabric for true decentralization, implement dynamic QR with OTP, deploy on AWS with auto-scaling, add HTTPS/TLS, integrate with CDSCO database. Current focus is proving ML/blockchain concepts work."

**Q: "Why not use existing solutions like TraceLink?"**

> "TraceLink requires proprietary apps (low adoption), costs ₹50L+ setup, takes 6-12 months deployment. We're browser-based (zero-app), ₹5-10L total, 2-3 weeks deployment. Built specifically for Indian market with local language support. Plus we add AI layer TraceLink doesn't have."

**Q: "How do you handle QR photocopy attacks?"**

> "Three layers: (1) Frequency analysis - flag if same QR scanned 15+ times in 1 hour, (2) Geospatial analysis - detect impossible travel speeds, (3) Future: Dynamic QR with time-based OTP that expires every 5 minutes, making photocopies useless."

**Q: "What if database is compromised?"**

> "Blockchain provides audit trail. Even if attacker modifies database, chain verification fails. For production: database encryption at rest, role-based access control, regular backups to immutable storage, separate read-replicas for public queries. Blockchain hashes stored separately can verify database integrity."
